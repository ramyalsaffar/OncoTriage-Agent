# Exception and Fallback Audit

Companion to item 11b (retrieval observability) and item 12 (age reference date
and partial birth dates). The project rule is that no
exception is caught without either being re-raised or recorded in a counter,
and that any fallback path logs which path was taken. This file is the
inventory that rule needs in order to be checkable: every `except` clause in
the codebase, and every non-exception degradation path, with a verdict.

**Scope.** All 41 `*.py` files in `03- Code/`, including the test scripts;
handlers were found in 24 of them.
**Last swept:** after the ECOG availability metric item (files 03, 20, 41).

> **ITEM 11a (degraded dependencies) CLOSED FOUR ROWS and the handler table
> below has NOT been re-swept for them.** The four are the two highest-priority
> `SILENT` rows in the production path (`min_age`/`max_age`, `_normalize_lab_unit`),
> the index-time `minimumAge` mirror, and the `08-` line-359 `ImportError`. Each
> carries its new verdict inline. See "What item 11a changed" below for the
> layer-level story, which the AST sweep cannot see at all — a detection layer
> that was never built raises no exception.

> **STALE FILE/LINE REFERENCES FOR FIVE FILES, as of item 20c pass 20c-3a.**
> Files 04, 05, 06, 11 and 12 moved into the package. Every handler this
> inventory attributes to one of them now lives in the corresponding module:
> `04-` → `oncotriage/fhir/generate.py`, `05-` → `oncotriage/fhir/clean.py`,
> `06-` → `oncotriage/fhir/explore.py`, `11-` → `oncotriage/retrieval/indexer.py`,
> `12-` → `oncotriage/retrieval/index_validator.py`. The line numbers have
> shifted; the handlers themselves are unchanged, which was proved by
> `ast.unparse` equivalence against `git show HEAD:` for all 84 top-level
> definitions. Earlier passes moved Files 07, 08, 09, 10, 13 and 14 the same
> way. **The sweep needs re-running against the package before this table is
> trusted for a line number again.**
**Method.** The handler table is generated by an AST sweep, not by hand, so it
cannot drift from the code without the line numbers moving. Dispositions are
assigned mechanically from the handler body:

| Disposition | Meaning |
|---|---|
| `RE-RAISES` | The handler raises — the original, a wrapper, or `SystemExit`. |
| `RECORDED+LOGGED` | Increments a counter / appends to a failure list **and** prints. |
| `RECORDED` | Increments a counter, appends to a failure list, or returns a value that carries the error text. Nothing printed. |
| `LOGGED` | Prints or logs only. Recovery leaves no counted trace. |
| `SILENT` | Neither. `pass`, `continue`, or a substituted default value. |

`LOGGED` and `SILENT` are the two that need reading. A printed WARNING on a
long batch run is not a record: item 11b exists because two of them
(`node_query_expansion`'s MeSH fallback and `node_hybrid_retrieval`'s
per-channel catch) were the only trace of a degraded inference, and the runs
they described could not be found again afterwards.

To regenerate the table, run the sweep below from `03- Code/`. It is reproduced
in full rather than described, because "generated by an AST sweep" is only a
checkable claim if the sweep can be re-run — and the first two ECOG items each
noted the audit was stale rather than closing the gap, which is exactly what an
unrunnable method invites.

```python
# audit_sweep.py — run from 03- Code/:  python audit_sweep.py > handlers.md
import ast, glob, os, collections

LOG_NAMES  = {"print", "warn"}
LOG_ATTRS  = {"debug", "info", "warning", "error", "critical", "exception",
              "write", "warn"}
LOG_OWNERS = {"logger", "log", "logging", "tqdm", "st", "warnings"}

def _mentions(node, name):
    return bool(name) and node is not None and any(
        isinstance(n, ast.Name) and n.id == name for n in ast.walk(node))

def classify(h):
    if any(isinstance(n, ast.Raise) for s in h.body for n in ast.walk(s)):
        return "RE-RAISES"
    for s in h.body:                                   # SystemExit via sys.exit()
        for n in ast.walk(s):
            if (isinstance(n, ast.Call) and isinstance(n.func, ast.Attribute)
                    and isinstance(n.func.value, ast.Name)
                    and n.func.value.id == "sys" and n.func.attr == "exit"):
                return "RE-RAISES"
    logged = recorded = False
    for s in h.body:
        for n in ast.walk(s):
            if isinstance(n, ast.Call):
                f = n.func
                if isinstance(f, ast.Name) and f.id in LOG_NAMES:
                    logged = True
                elif isinstance(f, ast.Attribute):
                    if f.attr in ("append", "add", "extend", "update"):
                        recorded = True
                    if (f.attr in LOG_ATTRS and isinstance(f.value, ast.Name)
                            and f.value.id in LOG_OWNERS):
                        logged = True
            if isinstance(n, ast.AugAssign):
                recorded = True
            # Assignment to a plain NAME whose value carries the error text.
            # Assignment to a SUBSCRIPT does not count: writing a status into a
            # dict the caller may or may not read is not, on its own, a record.
            if isinstance(n, ast.Assign) and any(
                    isinstance(t, ast.Name) for t in n.targets) \
                    and _mentions(n.value, h.name):
                recorded = True
            if isinstance(n, ast.Return) and _mentions(n.value, h.name):
                recorded = True
    return ("RECORDED+LOGGED" if recorded and logged else
            "RECORDED" if recorded else "LOGGED" if logged else "SILENT")

rows = []
for path in sorted(glob.glob("*.py")):
    src = open(path, encoding="utf-8").read()
    for n in ast.walk(ast.parse(src)):
        if isinstance(n, ast.ExceptHandler):
            body = " | ".join(
                " ".join((ast.get_source_segment(src, s) or "").split())
                for s in n.body)
            rows.append((os.path.basename(path), n.lineno,
                         ast.unparse(n.type) if n.type else "bare",
                         classify(n), body[:100]))
rows.sort(key=lambda r: (r[0], r[1]))
```

**Where the rules bite.** Two decisions in `classify()` account for every
disposition that is not obvious from reading the handler:

- A `+=` or an `.append(` is a record even when the value never leaves the
  process; a `print` is not. That is why `13-`'s batch-scroll handler, which
  does `trials_lost += ...` **and** prints, is `RECORDED+LOGGED` rather than
  `LOGGED`.
- Assigning into a **subscript** is not a record. `13-`'s two per-channel
  handlers write `retrieval_channels[channel] = {...}` and print; they are
  `LOGGED`. What makes that degradation recoverable is not the assignment but
  `_pipeline_provenance()` carrying the dict to the stored row — which is a
  property of the pipeline, not of the handler, and the sweep cannot see it.
  Read those two rows together with the item 11b table above.

Both new degradation paths are recorded rather than merely survived:
`BIRTH_DATE_PRECISION_COUNTS` tallies the shape of every `birthDate` in a load
and `load_all_patients` prints it; `PARTIAL_DATE_DEGRADATIONS` (File 02) counts
well-formed but impossible components (`1965-02-30`); and
`inferences.birth_date_precision` carries the per-patient value into the row,
where `"day"` means an exact age and `"month"` / `"year"` mean the age was
imputed. `NULL` in either new column means the parser did not report — not that
the date was exact and not that the age was computed against today.

The reference date is the corpus **snapshot** date rather than an arbitrary
frozen constant, so reproducibility does not come at the price of the ages
becoming fiction: every event in a bundle predates generation. Regenerating the
corpus means updating `DATA_SNAPSHOT_DATE`, and every run affected by the shift
is identifiable by its `age_reference_date`.

`get_age_reference_date()` raises rather than falling back to `date.today()`
when `DATA_SNAPSHOT_DATE` is unset or partial. That is deliberate and is the
one place in this file where a fallback was deliberately *not* added: a silent
fall back to the clock is the exact defect the constant exists to remove.

Measured on 25 real bundles: all 25 `birthDate` values are full dates and all
50 race/ethnicity reads resolve from `ombCategory`, so the stored values on the
Synthea corpus are unchanged by the extension fix — it is real EHR exports and
Safe Harbor de-identified records the old code would have lost. The ages moved:
8 of 25 differed from the `now()`-derived value, which is the drift that had
been accumulating in the prompt since the corpus was generated.

### The empty sparse vector question, settled

Both halves were measured before any code was written, and are re-measured by
`37- Retrieval Observability Test.py`.

1. **Can a query tokenize to nothing?** Yes. FastEmbed `Qdrant/bm25` returns
   zero indices for an empty string, whitespace, punctuation-only and
   stopword-only text. And the pipeline can produce such a text:
   `is_primary_cancer()` matches on code alone, so a condition with a
   recognized code and no display text is a primary cancer whose display is
   `""`; on the MeSH-fallback path Stage 1 sets every rerank query to that
   display, and `disease_query` — which feeds `title-bm25` and
   `conditions-bm25` — is then empty. The expanded query keeps its literal
   `", solid tumor, solid neoplasm"` suffix, so `criteria-bm25` and the dense
   channel are never exposed. **Exposure: two of four channels.**
2. **Does Qdrant reject an empty sparse vector?** No. Measured against a real
   Qdrant server v1.18.3 carrying three IDF sparse fields shaped like the
   production index: the query is accepted and returns zero points, on every
   field, with no exception and no 4xx.

So the failure mode was never a crash — it was two channels reporting a clean
zero that no stored record could tell apart from "this query matched nothing".
The guard added is therefore an **observability** guard, not a crash guard: it
raises before the network call because there is nothing to ask, and the point
of raising is to give the outcome its own status.

### The degradation the judge could not see

Section 2 of the Stage 5 system prompt told the model that disease relevance
"has already been confirmed" and then forbade it from assessing relevance.
Stage 4's cancer site filter is conditional on three things — the MeSH data
files being loaded, the patient resolving to specific C04 trees, and the
ablation flag being off — so in three of four cases the model was handed a
false premise together with a rule preventing it from noticing.

Two things limited the damage, and are recorded here rather than assumed:

- The indexed corpus is oncology-only, so the loose reading of the sentence
  ("every trial is a cancer trial") holds regardless. What fails is the
  narrower claim, that the trial matches *this patient's* cancer site.
- RULE 3's categorically-different-diseases branch already turns an off-site
  trial into a criterion-level `not_met` whenever the criteria name the
  disease, which most oncology criteria do.

**Residual exposure:** a trial whose criteria never state the disease,
evaluated for a patient whose site was never checked. Section 2 is now
conditional: when the filter ran it asserts confirmation as before; when it did
not, it says so, names the reason, and lifts the prohibition for exactly that
case — relevance may enter only as a RULE 3 criterion-level classification,
never as a trial-level rejection. Absent state is treated as "did not run".

**Behaviour change to record:** the `no_mesh_filter` ablation config now varies
the Stage 5 prompt as well as the Stage 4 filter, so its numbers are not
directly comparable with rows collected before this change. That is the
intended direction — telling the judge a false thing was part of what the old
configuration measured — but a mixed-vintage `ablation_results.db` should be
split on `mesh_filter_skip_reason`.

## What item 11a changed

Item 11b was about a stage that failed and left no trace. **Item 11a is about a
LAYER that was never there and left no trace** — a different failure, because
nothing failed at all: the pipeline ran, produced matches, logged a warning to a
console nobody was watching, and every downstream number was computed as if the
missing layer had agreed with the rest.

**Two layers could disappear from a missing file or a missing pip package, and
both now RAISE by default.**

| Layer | Was | Is |
|---|---|---|
| MeSH C04 site relevance (`registries/mesh.py:load_mesh_filter`) | prints a warning, returns `None`; Stage 4's cancer site filter never runs and **every trial passes it for the whole run** | raises `settings.DegradedDependencyError` naming both missing JSON files, the command that builds them, and the opt-out |
| ICD-10-CM cancer codes (`registries/cancer_code_registry.py:_build_icd10_cancer_sets`) | catches `ImportError`, `logger.error`, returns **three empty sets** while the registry goes on logging "CancerCodeRegistry ready" | raises, naming the package and `pip install icd10-cm`, and says that the C77-C79 / D00-D49 **exclusion** sets go with the primary ones |

**`None` is still a reachable state and every branch handling it is still real.**
Stage 4 records four distinct skip reasons and File 37 installs
`deps.set_override(deps.MESH_FILTER, None)` to exercise one of them. What item
11a removed is the ability to CREATE that state silently from missing files. It
now arrives only from an override, or from an operator who set the variable.

**The opt-out.** `ONCOTRIAGE_ALLOW_DEGRADED_REGISTRIES=1`
(`oncotriage/settings.py`, deliberately not routed through `_from_env`, which
appends a trailing separator and would make the flag never match). When set, the
run continues, logs at WARNING naming exactly which layer is absent and which
variable permitted it, and records the layer in a module-level counter
(`MESH_FILTER_DEGRADATIONS`, `REGISTRY_DEGRADATIONS`). Per inference the MeSH
case was already recorded, by item 11b, in `mesh_filter_skip_reason` — no new
column and no new field. An unrecognised value **raises** rather than being read
as "off".

**The opt-out does not reach the deletion path, and that is the point.**
`oncotriage/fhir/clean.py:require_intact_registry()` refuses a degraded registry
whatever the variable says, because `filter_cancer_patients_inplace()` unlinks
patient bundles on `is_primary_cancer()` verdicts — a degraded registry there
means a missing pip package deletes the dataset, and it gets it wrong in BOTH
directions (ICD-10-coded cancers deleted as non-cancer; in-situ and
metastatic-only records admitted by the display-term fallback). A registry that
cannot report whether it is intact is refused too. That refusal is demonstrated
with the variable SET, in `48- Degraded Dependency Test.py` section 5.

**`filter_cancer_patients_inplace(dry_run=True)`** reports exactly what it would
delete, writes the full list to `{manifest}.dryrun`, and deletes nothing. One
`if` around the unlink, so the plan and the deletion are one code path.

**Three paths COUNT rather than raise, and the distinction is not arbitrary.** A
missing file or package is a CONFIGURATION defect: one command fixes it and
every run afterwards is correct, so raising costs one run and fixes the class.
An unparseable trial age bound or an unrecognised lab unit is third-party DATA —
there is no operator action that would fix ClinicalTrials.gov — and raising
would convert a per-trial degradation into a per-patient outage. Those get the
counters this file asked for; see the three CLOSED rows below.

**Two guards were added that no row here asked for**, because the sweep that
produced this file can only see `except` clauses:

- the ICD-10 build raises when the package **imports and yields no primary
  codes**. A release whose chapter-2 categories moved produces exactly the three
  empty sets the missing-package path produced, with the import succeeding, so
  neither the old handler nor the new raise could see it on its own. Its first
  form (`if not primary:`) could never fire — `_ICD10_SEED_PRIMARY` seeds `C97`
  unconditionally — and the negative control in File 48 is what found that, not
  reading;
- `require_intact_registry()` refuses an object that does not report
  `degraded_layers` at all. "Cannot tell" is not "is fine", and only one of the
  two may proceed to delete.

**Covered by** `48- Degraded Dependency Test.py` — 170 assertions, no network,
no key, no corpus written to. Every raise is demonstrated to fire with the file
or package absent **and** demonstrated not to fire with it present; the dry run
is demonstrated against a copy of a real cohort with a real run on an identical
second copy as the control.
